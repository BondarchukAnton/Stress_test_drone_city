# Stress Test Drone City

Мультиагентная система для роя дронов. Агенты на базе LLM координируют
обследование города, тушение пожаров, доставку грузов и другие миссии.

## Как это работает

У каждого дрона и ровера есть **агент** — программа, которая принимает
решения через языковую модель (LLM). Агенты общаются через общую **доску**
(blackboard): координатор ставит задачу, дроны предлагают план, обсуждают,
распределяют зоны и выполняют полёт.

Связь агента с физическим дроном идёт через **мост** (bridge) — HTTP-сервер
на борту, который даёт команды: «сфотографируй», «лети в клетку X,Y»,
«проанализируй снимок», «посади дрон для замены батареи». Один и тот же
интерфейс моста работает и с моком (для отладки на ноутбуке), и с
настоящим дроном на PX4/ROS2.

```
┌── Хост-ПК (запуск агентов) ──────────────────────────────────────────┐
│                                                                      │
│  coordinator ──┐                                                     │
│  drone-1..4 ───┤   принимают решения,    ┌──────────────────────┐    │
│  rover ────────┼── пишут в общую доску   │  blackboard/         │    │
│                │                         │  ├ phase.json        │    │
│  hub :8095 ────┤── дашборд + SSE-стрим   │  ├ messages/         │    │
│                │                         │  └ events.jsonl      │    │
│                │   HTTP                   └──────────────────────┘    │
│         ┌──────┴──────┐                                              │
│         │  bridge      │  ← один мост на каждый борт                 │
│         │  mock.py     │    (мок для разработки без дронов)          │
│         └──────┬──────┘                                              │
└────────────────┼─────────────────────────────────────────────────────┘
                 │ HTTP (один и тот же контракт)
┌────────────────┼─────────────────────────────────────────────────────┐
│   Борт дрона   │                                                     │
│         ┌──────┴──────┐                                              │
│         │  bridge      │  ← реальный мост на борту (ROS2/PX4)        │
│         │  ros2/       │    тот же HTTP API, другая реализация       │
│         └──────┬──────┘                                              │
│              ROS2                                                    │
│         ┌──────┴──────┐                                              │
│         │  PX4 + Nav2  │  ← автопилот + навигация                    │
│         │  камера      │  ← сенсоры                                  │
│         └──────────────┘                                             │
└──────────────────────────────────────────────────────────────────────┘
```

## Что нужно для запуска

- Docker (есть в проекте docker-compose)
- API-ключ к LLM-провайдеру (Sverk, OpenAI, Anthropic или Ollama)
- Для реальных дронов: Raspberry Pi с PX4, ROS2 и камерой на каждом борту

## Быстрый старт (разработка без дронов)

Мок-мосты симулируют дронов — можно запустить всё на одном ноутбуке
и увидеть, как агенты договариваются, летают и выполняют миссию.

### 1. Настройка

Создай `.env` из шаблона (или используй готовый):

```bash
cp .env.example .env
```

Заполни ключи в `.env`:

```bash
# Провайдер LLM (выбери один)
MODEL_PROVIDER=sverk            # или anthropic, openai, ollama
MODEL=gemma4-vlm                # модель у провайдера

# Ключ — только тот, что нужен твоему провайдеру
SVERK_API_KEY=sk-...            # для sverk
# ANTHROPIC_API_KEY=sk-ant-...  # для anthropic
# OPENAI_API_KEY=sk-...         # для openai

# Без ключа агенты работают на мок-мозгах (детерминированные шаблоны)
```

### 2. Запуск city-миссии (пожар + доставка)

Без реального LLM (мок-мозги):
```bash
make city-mock
```

С реальным LLM:
```bash
make city-sverk
```

Дашборд откроется на http://localhost:8095 — ты увидишь фазу миссии,
мысли агентов, их переписку и события.

### 3. Остановка

```bash
make down       # выключить контейнеры
make reset      # удалить всё состояние (начать заново)
make logs       # логи всех сервисов
```

## Сценарии

Проект поддерживает несколько сценариев. Переключаются переменной `TASK`
в `.env`.

| Сценарий | TASK в .env | Что делают дроны |
|----------|-------------|------------------|
| Город дронов | `city_missions` | Обследуют город 6×6, находят пожар, тушат, доставляют груз между районами |
| Поиск груза | `survey` | Сканируют поле, ищут целевой груз, ровер едет к находке |
| Безопасный пролёт | `safe_passage` | Координатор + 4 скаута: облёт поля, детекция препятствий |
| Художники | `painting` | Дроны с баллончиками коллективно рисуют картину |

Сменить сценарий:
```bash
# В .env
TASK=survey
SCENARIO=survey-1
make city-sverk
```

## Как добавить свой сценарий

1. Создай `test_fixtures/my-scenario/map.json` с картой.
2. Добавь роль в `agent/roles/` (если нужна новая логика).
3. Пропиши `TASK` и `SCENARIO` в `.env` или docker-compose оверлее.

## Развёртывание на реальные дроны

Каждый дрон получает образ из `onboard/Dockerfile`. Подробности — в
[onboard/README.md](onboard/README.md) и [docs/real_drone_setup.md](docs/real_drone_setup.md).

Кратко:

```bash
# На каждом дроне (Raspberry Pi с Docker):
# 1. Скопировать onboard/ на дрон
# 2. Настроить onboard/.env.drone:
#    HANDLER_ID=team-7
#    FLEET=city
#    HUB_URL=http://<IP_хаба>:8080
#    MODEL_PROVIDER=sverk
#    MODEL=gemma4-vlm
#    SVERK_API_KEY=sk-...
#
# 3. Запустить:
docker compose -p $AGENT_ID -f docker-compose.drone.yml --env-file .env.drone up -d
```

Можно добавить дрона на лету — он зарегистрируется в хабе и координатор
включит его в следующую миссию.

## Использование с симулятором

Для отладки полётной логики можно подключить агентов к симулятору
Gazebo + PX4 + ROS2 вместо реальных дронов. Для этого нужно заменить
мок-мосты на `bridge/ros2/bridge_node.py` и обеспечить сетевую связность
с симулятором. Детали — в [docs/sitl_setup.md](docs/sitl_setup.md).

## FAQ

**Q: Обязательно ли нужен API-ключ?**
A: Нет. Без ключа агенты используют детерминированные шаблоны (мок-мозги).
   Для реальной координации нужен ключ к LLM-провайдеру.

**Q: Сколько дронов поддерживается?**
A: Базовый сценарий — 4 дрона + ровер. Можно добавить больше через
   docker-compose оверлей и переменную SCOUTS.

**Q: Можно ли использовать локальную модель?**
A: Да: `MODEL_PROVIDER=ollama`, `OLLAMA_BASE=http://localhost:11434`.
   Качество ниже, но работает без интернета.

**Q: Где посмотреть, что происходит?**
A: Дашборд на http://localhost:8095 показывает фазу, агентов, их мысли
   и переписку в реальном времени.
